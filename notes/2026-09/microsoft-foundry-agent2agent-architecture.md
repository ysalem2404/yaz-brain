# Microsoft Foundry Agent2Agent Architecture

![Infographic](/img/notes/2026-09/microsoft-foundry-agent2agent-architecture.png)

## Summary
An enterprise architecture explainer positions A2A as a standard for agent-to-agent collaboration and MCP as the complementary protocol for connecting agents to tools and resources.

## Key points
- A2A replaces tightly coupled, custom integrations with standardized agent communication, discovery, and invocation.
- Its building blocks include Agent Cards, Skills, Messages, Tasks, Artifacts, and Parts; a registry becomes more important as the number of agents grows.
- The diagram shows both incoming A2A, where Foundry exposes an agent, and outgoing A2A, where a Foundry agent invokes a remote specialist.
- MCP handles agent-to-tool/resource connections, while A2A connects agents to agents; the framework pairs interoperability with identity, RBAC, least privilege, network isolation, observability, and lifecycle controls.

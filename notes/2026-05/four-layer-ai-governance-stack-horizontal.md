# The Four-Layer AI Governance Stack: Why Horizontal Governance Wins

![Infographic](public/img/notes/2026-05/four-layer-ai-governance-stack-horizontal.png)

## Summary
Argues that '64% of organisations managing AI governance tool-by-tool report inconsistent policy application within 12 months' (citing Deloitte AI in Financial Services, 2025), and proposes a 4-layer horizontal governance stack instead: (1) Access Control — org-managed accounts only, binary test 'is every user accessing AI tools only through an organisation-managed account?'; (2) Data Classification — a defined off-limits data list with pre-upload scanning; (3) Tool Certification — a central vetted-tool register reviewed quarterly; (4) Spend & Usage Governance — group-level spend limits tracked against actual usage. Core argument: per-tool governance creates a new policy for every new tool ('compounding complexity'), while horizontal governance applies one framework across all tools ('consistent, scales clean').

## Key points
- Cites a concrete stat: 64% of orgs with tool-by-tool AI governance see inconsistent policy within 12 months (Deloitte 2025)
- Each layer ships with a literal binary yes/no audit test — designed for compliance checklisting
- Core thesis: 5 tools × 5 policies = compounding complexity; 5 tools × 1 framework = linear, auditable scaling
- Spend governance is treated as a first-class governance layer, not just a FinOps concern
- Explicit implication: before adding any new AI tool, check whether the existing governance stack already covers it

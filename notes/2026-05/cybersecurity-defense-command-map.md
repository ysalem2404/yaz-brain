# Cybersecurity Defense Command Map

![Infographic](public/img/notes/2026-05/cybersecurity-defense-command-map.png)

## Summary
A full command-map of enterprise cybersecurity functions branching from a central 'CYBER' node: Defense (Prevent/Protect/Security Governance with MFA, conditional access, EDR/XDR/SIEM/UEBA under Detect), Access (least privilege), Harden (cloud/network/identity/devices), Response (Contain→Eradicate via alert/identity/endpoint investigate-reset-isolate), Operations (Verify/Authorize/Block), Engineering (Cloud, AppSec, Data, AI Security, Third-Party — with AI Security specifically listing 'AI guardrails,' 'model access,' and 'prompt injection'), and Resilience (Recovery/Continuity with immutable backup and cyber-recovery tabletops). Bottom layer maps Security Analytics (baseline→correlate→prioritize→monitor→score) to the NIST-style Security Functions (govern/identify/protect/detect/respond/recover/improve).

## Key points
- AI Security is called out as its own Engineering sub-branch alongside Cloud/AppSec/Data — with prompt injection and model access as named risks
- Response workflow is explicit: Contain → Eradicate, broken into alert/identity/endpoint tracks each ending in a concrete action
- Resilience separates Recovery (immutable backup, restore testing) from Continuity (cyber recovery, tabletop exercises)
- Bottom band aligns Security Analytics maturity steps directly to the govern-identify-protect-detect-respond-recover-improve function set
- Supply chain risk appears under AppSec (SBOM) not as a standalone category

## Entities & tools mentioned
Excellog.Biz, CSPM, CNAPP, CASB, SAST, DAST, SBOM

## Why I saved this
Single-page reference for briefing Bechtel security stakeholders on where AI-specific risks (prompt injection, model access, guardrails) sit inside the existing enterprise security taxonomy — critical for FedRAMP/GCCH boundary discussions.
